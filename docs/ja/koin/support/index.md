# バージョン、ロードマップおよびサポート

このページでは、Koin のバージョンがどのように付与・リリースされるか、また各バージョンに対してどのようなサポートが提供されるかについて説明します。Koin はオープンソースであり、コミュニティによって主導されています。また、Koin を開発している企業である Kotzilla は、それを必要とするチーム向けに商用の長期サポート（LTS）も提供しています。

## リリースサイクル {id="release-cycle"}

Koin は、Kotlin 言語やライブラリのアップデートと歩調を合わせるため、約6か月のリリースサイクルに従っています。各リリースは、フィードバックを収集するために6週間以上のベータ期間を経ます。

バージョンがリリースされると、そのコミュニティサポートフェーズは最低6か月間継続します。このフェーズ中、チームはフィードバックを収集し、Koin に影響を与える Kotlin、Android、Ktor、その他のライブラリのアップデートに追従します。

各バージョンの変更点については、[Releases & Upgrade Guides](/docs/support/releases) を参照してください。

## バージョン番号 {id="version-numbers"}

Koin のバージョンは `メジャー.マイナー.パッチ`（`Major.Minor.Patch`）の形式に従います。

- **パッチ（Patch）**: 不具合の修正のみ、および依存ライブラリのマイナーアップデート。
- **マイナー（Minor）**: 新機能の追加と非推奨（deprecation）の指定。
- **メジャー（Major）**: 影響の大きい新機能、非推奨の指定、および互換性を破る変更（breaking changes）。

プレリリースのサフィックス（alpha、beta、RC）や、`@KoinExperimentalAPI` および `@Deprecated` の意味については、[API Stability](/docs/support/api-stability) で説明されています。

## コミュニティサポート {id="community-support"}

コミュニティサポートは、現在のリリースラインにおいて誰でも利用可能です。

- **GitHub Issues**: [github.com/InsertKoinIO/koin](https://github.com/InsertKoinIO/koin) でのバグレポートおよび機能リクエスト。
- **ドキュメント**: 本サイト、[insert-koin.io](https://insert-koin.io)。
- **Slack**: [Kotlin Slack #koin](https://kotlinlang.slack.com/messages/koin/) でのコミュニティディスカッション。
- **Stack Overflow**: [koin](https://stackoverflow.com/questions/tagged/koin) タグが付いた質問。
- **リリースノート**: [Releases](/docs/support/releases) 内のアップグレードガイド。

## Kotzilla によるエンタープライズサポート {id="enterprise-support-by-kotzilla"}

企業によっては、法 compliance（法務）、ビジネス、または技術的な理由から、Koin のリリースサイクルに追従できない場合があります。また、企業による保証付きのサポートや、明確なオープンソースライセンスの保証が必要な場合もあります。

Kotzilla は、これに対応する2つのエンタープライズサブスクリプションを提供しています。どちらも同様の仕組みです。お客様自身が管理するバージョンに固定された、非公開でメンテナンスされる Koin のビルドが提供され、最新のパブリックリリースだけでなく、そのビルドに対しても修正が提供されます。

- **[Koin LTS](#long-term-support-lts)**: 特定のバージョンに留まる必要があるアプリケーション向けの、`org.koin.*` 配下で公開されるメンテナンス対象の Koin ライン。
- **[Koin Embedded LTS](#koin-embedded-lts)**: SDK およびライブラリベンダー向け。お客様専用の名前空間（namespace）にリロケート（再配置）された、独自の Koin LTS バージョン。

プロフェッショナルな Koin サポートは、LTS または Embedded LTS のサブスクリプションとして契約されます。その上に別個のティア（階層）はありません。SLA、アーキテクチャレビュー、トレーニングなどのコミットメントは、そのサブスクリプションに対する[アドオン](#add-on-services)となります。

### 長期サポート（LTS: Long-Term Support） {id="long-term-support-lts"}

LTS ラインとは、コミュニティサポートフェーズが終了した後も Kotzilla がメンテナンスを継続する Koin バージョンのことです。セキュリティ修正やお客様から報告されたバグの修正がバックポートされ、サブスクリプション契約者に公開されるため、既知の不具合を抱えることなく特定のバージョンを使い続けることができます。

サポートポリシー:

- **最低期間**: 各 LTS ラインは、その指定から最低18か月間保証されます。これは最低保証期間（floor）であり、終了スケジュールではありません。
- **適用範囲**: サポートは、その期間を超えても、お客様が実行しているバージョンにおいてサブスクリプションが有効である限り継続します。18か月という期間は、ラインを指定して維持するコミットメントの期限です。サポートの適用範囲は、本ページに掲載されている日付ではなく、お客様の契約によって定められます。
- **新しいライン**: 主要な Kotlin のベースラインごとに新しい LTS ラインが指定され、前のラインからの移行ガイドが提供され、カバレッジにギャップが生じることはありません。移行中にサポート対象外の状態で運用する必要はありません。

このページではサポート終了日を公開していません。適用範囲はお客様のサブスクリプションおよび実行しているバージョンに従い、契約書に明記されます。

#### 提供中の LTS ライン {id="available-lts-lines"}

2つのラインは、順次ではなく並行してメンテナンスされています。プロジェクトの Kotlin ベースラインに一致するものを選択してください。サポートを受けるために `3.5.6` から移行する必要はありません。

| LTS ライン | Kotlin ベースライン | 対象 |
|----------|-----------------|--------------|
| Koin 3.5.6 LTS | Kotlin 1.x | Kotlin 2.x に移行できないプロジェクト: レガシーなツールチェーン、長期運用のエンタープライズアプリ、制約のあるビルド環境 |
| Koin 4.2.x LTS | Kotlin 2.x | 各リリースに追従する代わりに、固定されメンテナンスされた Koin バージョンを希望する Kotlin 2.x ツールチェーン上のプロジェクト |

:::note
LTS ラインは特定のパッチレベルで指定され、そのパッチレベルが最低要件となります。`3.5.6` は Kotlin 1.x ラインにおいてサポートされる最低バージョンです。これより前のバージョンはサポート対象外です。現在より古いパッチを使用している場合、LTS パッチレベルへの引き上げがオンボーディングの一環となります。
:::

Kotlin 1.x ラインから Kotlin 2.x ラインへのアップグレードはプランに含まれています。Koin チームがガイドし、移行中も現在のラインのサポートが継続されます。

#### 含まれる内容 {id="what-s-included"}

- **メンテナンスと互換性**: お客様が運用する LTS ライン上で維持される、Android および Kotlin エコシステムとの機能互換性。
- **サポート**: Slack および専用メールを通じた、Koin チームへの優先アクセス。
- **法的コンプライアンス**: 監査済みの Apache 2.0 ライセンス。Kotzilla がお客様のコンプライアンスに責任を持ちます。
- **透明性**: コードベースへの完全なアクセス、およびコミュニティによって特定された修正の該当ラインへの統合。

### Koin Embedded LTS {id="koin-embedded-lts"}

Koin を内部で使用する SDK やライブラリを出荷する場合、`org.koin.*` 配下で公開すると、ホストアプリケーションの Koin バージョンや、同じアプリ内で同様に Koin を組み込んでいる他の SDK と衝突（コンフリクト）します。

Koin Embedded LTS はこれを解決します。衝突のない、最低18か月間メンテナンスされるお客様専用の Koin LTS バージョンです。Kotzilla はメンテナンス対象の [LTS ライン](#available-lts-lines) をお客様専用の名前空間へとリロケートし、ビルド、署名、ホスティング、メンテナンスを代行します。これは `koin-core` および `koin-android` をカバーします。

また、異なるトレードオフを持つ、リロケートされた Koin を取得するための無料のセルフサービス方式もあります。[Koin for SDK & Libraries](/docs/support/embedded) では、衝突の事例、セルフサービスの選択肢、および[完全な Embedded LTS プラン](/docs/support/embedded#koin-embedded-lts)の両方を扱っています。

### サポートティア {id="support-tiers"}

| | コミュニティ | Koin LTS | Koin Embedded LTS |
|---|---|---|---|
| 対象 | すべての方: アプリ、オープンソースプロジェクト、最新リリースを利用しているチーム | 特定の Koin バージョンに留まる必要がある企業 | アーティファクト内に Koin を組み込んで出荷する SDK およびライブラリベンダー |
| 提供バージョン | 最新のパブリックリリース | 指定された LTS ライン（プライベートにメンテナンス） | 指定された LTS ライン（お客様の名前空間にリロケート） |
| 名前空間 | `org.koin.*` | `org.koin.*` | お客様専用の名前空間（例: `acme.koin.*`） |
| 配布方法 | Maven Central | Kotzilla リポジトリ（お客様の認証情報によるプライベートアクセス） | Kotzilla リポジトリ（お客様の組織専用のプライベートリポジトリ） |
| セキュリティパッチ | 現在のリリースラインのみ | お客様の LTS ラインへバックポート | バックポートされ、お客様のビルド用に再度リロケート |
| お客様固有の課題の修正 | ベストエフォート（公開 GitHub Issues 経由） | 修正のうえ、お客様の LTS ビルドで提供 | 修正のうえ、お客様のビルドで提供 |
| Koin チームへの直接チャネル | なし（公開 Slack および GitHub のみ） | 優先アクセス（Slack および専用メール経由） | 優先アクセス（Slack および専用メール経由） |
| アップグレード支援 | 公開マイグレーションガイド | LTS ライン間のガイド付きアップグレード | ガイド付きアップグレード、移行先バージョン用にリロケーションを再ビルド |

### アドオンサービス {id="add-on-services"}

これらは Koin LTS または Koin Embedded LTS サブスクリプションに追加して契約するものです。別個のティアではありません。

- **サービスレベルアグリーメント（SLA）**: 契約による応答時間の保証。
- **アーキテクチャレビュー**: Koin チームによる Koin のセットアップおよびモジュール構造のレビュー。
- **トレーニングとワークショップ**: Koin の実践手法に関するチーム向けトレーニング。

条件は契約ごとに合意されます。対象範囲については[チームにお問い合わせ](#contact)ください。

### ティアの選択 {id="choosing-a-tier"}

- **コミュニティ**: 最新の Koin リリースに追従しており、パブリックサポートで十分な場合。
- **Koin LTS**: 特定のバージョンに留まる必要があり、そのバージョンでの修正が必要な場合。
- **Koin Embedded LTS**: 独自のアーティファクト内で Koin を再配布しており、利用先との名前空間の衝突を回避したい場合。
