Kotlin Early Access Preview（EAP）に参加すると、Kotlin の最新機能が正式リリースされる前にお試しいただけます。

言語リリース（_2.x.0_）およびツールリリース（_2.x.20_）の前に、実際のプロジェクトでテストして早期にフィードバックを共有していただけるよう、Early Access Preview（EAP）ビルドを提供しています。
Kotlin EAP ビルドには、通常以下のステージが含まれます:

| EAP ビルド | 説明                                                                                                                                                                                              |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Beta1** | 今後追加される機能の第1弾、改善、およびその他の重要な変更を導入します。新機能をいち早く評価し、フィードバックを共有する機会を提供します。                             |
| **Beta2** | 通常、受け取ったフィードバックに基づいてさらなる機能や改良を追加します。機能的に完成（feature-complete）しており、今後のリリースのプレビューを継続しながら、以前に導入された機能をさらに成熟させます。 |
| **RC**    | 最初のリリース候補版（Release Candidate）。Beta1 と Beta2 で提供された変更の安定化や、テスト中に見つかったリグレッションの修正に重点を置きます。                                                        |
| **RC2**   | リリースを確定し、準備が完了していることを確認するための重要な修正が含まれます。                                                                                                                                  | 

バグを見つけた場合は、課題トラッカーである [YouTrack](https://kotl.in/issue) にご報告いただけると助かります。
多くの場合、正式リリース前に修正できるため、問題の解決を次の Kotlin リリースまで待つ必要がなくなります。

Early Access Preview に参加してバグを報告することで、Kotlin に貢献し、[成長し続ける Kotlin コミュニティ](https://kotlinlang.org/community/)のすべての人のために Kotlin をより良く改善する力となります。

質問がある場合や議論に参加したい場合は、お気軽に [Kotlin Slack の #eap チャンネル](https://app.slack.com/client/T09229ZC6/C0KLZSCHF) にご参加ください。
このチャンネルでは、新しい EAP ビルドに関する通知を受け取ることもできます。

**[Kotlin EAP バージョン向けのプロジェクトの設定](configure-build-for-eap.md)**

> EAP に参加することにより、EAP バージョンが信頼できない可能性があり、意図したとおりに動作しない可能性があり、エラーが含まれる可能性があることを明示的に認めるものとします。
>
> 同一リリースの EAP バージョンと最終バージョンの間の互換性は保証されません。 
>

## EAP を活用して Kotlin での生産性を高める方法 {id="how-the-eap-can-help-you-be-more-productive-with-kotlin"}

* **安定版（Stable）リリースへの備え**。複雑なマルチモジュールプロジェクトに取り組んでいる場合、EAP に参加することで、安定版リリースを採用する際のエクスペリエンスを効率化できます。安定版へのアップデートが早ければ早いほど、そのパフォーマンス向上や新しい言語機能のメリットを早期に享受できます。

  大規模で複雑なプロジェクトの移行には時間がかかる場合があります。これはプロジェクトの規模だけでなく、特定のユースケースが Kotlin チームによってまだカバーされていない可能性があるためです。EAP に参加して新しいバージョンの Kotlin を継続的にテストすることで、特定のユースケースに関する早期フィードバックを提供できます。これにより、可能な限り多くの問題に対処し、安定版がリリースされたときに安全にアップデートできるようになります。[Slack が Android、Kotlin、Gradle のプレリリース版をテストすることでどのようなメリットを得ているかをご確認ください](https://slack.engineering/shadow-jobs/)。
* **ライブラリを最新に保つ**。ライブラリの開発者にとって、新しい Kotlin バージョンへのアップデートは極めて重要です。古いバージョンを使用し続けると、ユーザーが自身のプロジェクトで Kotlin をアップデートできなくなる可能性があります。EAP バージョンを使用することで、安定版のリリースとほぼ同時にライブラリで最新の Kotlin バージョンをサポートできるため、ユーザーの満足度を高め、ライブラリの人気を向上させることができます。
* **知見の共有**。Kotlin の熱心なファンであり、教育コンテンツを作成して Kotlin エコシステムに貢献したいと考えている場合、Kotlin EAP で新機能を試すことで、その魅力的な新機能を使用した体験をコミュニティにいち早く共有できるようになります。
