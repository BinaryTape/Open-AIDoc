您可以參與 Kotlin 早期體驗預覽（Early Access Preview，EAP），在最新的 Kotlin 功能正式發佈前搶先試用。

在每次語言（_2.x.0_）與工具（_2.x.20_）版本發佈之前，我們都會提供 Early Access Preview (EAP) 組建，供您在實際專案中測試並分享早期回饋。
Kotlin EAP 組建通常包含以下階段：

| EAP 組建 | 描述 |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Beta1** | 引入即將推出的第一批功能、改進和其他重大變更。讓您有機會提早評估新功能性並分享回饋。 |
| **Beta2** | 通常會根據我們收到的回饋新增更多功能和完善現有內容。此階段功能齊備，並持續預覽即將發佈的版本，進一步讓先前引入的功能更加成熟。 |
| **RC**    | 第一個發行候選版本（Release Candidate）。重點在於穩定 Beta1 與 Beta2 中所提供的變更，並修復在測試過程中發現的迴歸問題。 |
| **RC2**   | 包含重要修復，以定稿發行版本並確認準備就緒。 | 

如果您將發現的任何錯誤回報至我們的問題追蹤器 [YouTrack](https://kotl.in/issue)，我們將不勝感激。
在大多數情況下，我們可以在最終發行版本之前進行修復，因此您不必等待下一個 Kotlin 版本才能看到您的問題獲得解決。

透過參與 Early Access Preview 並回報錯誤，您為 Kotlin 做出了貢獻，並幫助我們為[日益壯大的 Kotlin 社群](https://kotlinlang.org/community/)中的每個人打造更好的 Kotlin。

如果您有任何疑問或想參與討論，歡迎加入 [Kotlin Slack 中的 #eap 頻道](https://app.slack.com/client/T09229ZC6/C0KLZSCHF)。
在此頻道中，您也可以收到有關新 EAP 組建的通知。

**[為 Kotlin EAP 版本配置您的專案](configure-build-for-eap.md)**

> 參與 EAP 即表示您明確知悉 EAP 版本可能不可靠、可能無法按預期運作，且可能包含錯誤。
>
> 我們不保證同一發行版本的 EAP 與最終版本之間的相容性。
>

## EAP 如何幫助您提升 Kotlin 的生產力 {id="how-the-eap-can-help-you-be-more-productive-with-kotlin"}

* **為穩定版本（Stable release）做好準備**。如果您從事複雜的多模組專案開發，參與 EAP 可以讓您在採用穩定版本時獲得更順暢的體驗。您越早更新至穩定版本，就能越早享受其效能改進和全新語言特性的優勢。

  遷移龐大且複雜的專案可能需要一段時間，這不僅是因為其規模，也是因為某些特定使用案例可能尚未被 Kotlin 團隊涵蓋。透過參與 EAP 並持續測試 Kotlin 的新版本，您可以針對自身的特定使用案例向我們提供早期回饋。這將有助於我們解決盡可能多的問題，並確保您在穩定版本發佈時能夠安全地進行更新。[了解 Slack 如何從測試 Android、Kotlin 和 Gradle 預先發佈版本中獲益](https://slack.engineering/shadow-jobs/)。
* **保持程式庫處於最新狀態**。如果您是程式庫作者，更新至新的 Kotlin 版本至關重要。使用舊版本可能會阻礙您的使用者在他們的專案中更新 Kotlin。使用 EAP 版本可讓您的程式庫在穩定版本發佈時幾乎能立即支援最新的 Kotlin 版本，這能讓您的使用者更滿意，並使您的程式庫更受歡迎。
* **分享經驗**。如果您是 Kotlin 愛好者，並且樂於透過製作教學內容為 Kotlin 生態系統做出貢獻，那麼在 Kotlin EAP 中試用新功能，可讓您成為首批與社群分享使用這些酷炫新功能體驗的人之一。
