你可以參與 Kotlin Early Access Preview (EAP)，在最新 Kotlin 功能正式發佈之前搶先體驗。

在每個語言版本 (_2.x.0_) 和工具版本 (_2.x.20_) 發佈之前，我們都會推出 Early Access Preview (EAP) 組建，供你在實際專案中測試並分享早期回饋。
Kotlin EAP 組建通常包含以下階段：

| EAP 組建 | 說明                                                                                                                                                                                              |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Beta1** | 引入第一批即將推出的功能、改進和其他重大變更。讓你有早期機會評估新功能性並分享回饋。                             |
| **Beta2** | 通常會根據我們收到的回饋新增更多功能和改進。功能已完整（feature-complete），並繼續預覽即將發佈的版本，進一步完善先前引入的功能。 |
| **RC**    | 第一個發行候選版本（Release Candidate）。重點在於穩定 Beta1 和 Beta2 中提供的變更，以及修復測試期間發現的迴歸問題。                                                        |
| **RC2**   | 包含重要的修復程式，以完成版本的最終定稿並確認就緒狀態。                                                                                                                                  | 

如果你在問題追蹤器 [YouTrack](https://kotl.in/issue) 回報發現的任何錯誤，我們將不勝感激。
在大多數情況下，我們可以在最終發佈前修復它們，因此你無需等待下一個 Kotlin 版本即可看到問題得到解決。

透過參與 Early Access Preview 並回報錯誤，你將為 Kotlin 做出貢獻，並幫助我們為[不斷成長的 Kotlin 社群](https://kotlinlang.org/community/)中的每個人打造更好的 Kotlin。

如果你有任何問題或想加入討論，歡迎加入 [Kotlin Slack 中的 #eap 頻道](https://app.slack.com/client/T09229ZC6/C0KLZSCHF)。
在此頻道中，你還可以收到有關新 EAP 組建的通知。

**[為 Kotlin EAP 版本設定你的專案](configure-build-for-eap.md)**

> 參與 EAP 即表示你明確確認 EAP 版本可能不穩定、可能無法按預期運作，且可能包含錯誤。
>
> 我們不保證同一版本的 EAP 與最終版本之間的相容性。
>

## EAP 如何幫助你更有效率地使用 Kotlin {id="how-the-eap-can-help-you-be-more-productive-with-kotlin"}

* **為穩定版（Stable）做好準備**。如果你從事複雜的多模組專案開發，參與 EAP 可以讓你在採用穩定發佈版本時的體驗更加順暢。越早更新到穩定版本，就能越早利用其效能改善和新語言特性。

  龐大且複雜專案的遷移可能需要一段時間，不僅僅是因為其規模，還因為某些特定的使用案例可能尚未被 Kotlin 團隊涵蓋。透過參與 EAP 並持續測試 Kotlin 的新版本，你可以向我們提供有關你特定使用案例的早期回饋。這將幫助我們解決盡可能多的問題，並確保你在正式版發佈時可以安全地更新到穩定版本。[了解 Slack 如何從測試 Android、Kotlin 和 Gradle 預發佈版本中獲益](https://slack.engineering/shadow-jobs/)。
* **保持你的程式庫為最新狀態**。如果你是程式庫作者，更新到新的 Kotlin 版本極為重要。
  使用舊版本可能會阻止你的使用者在其專案中更新 Kotlin。使用 EAP 版本可讓你的程式庫在穩定版發佈時幾乎能立即支援最新 Kotlin 版本，這能讓你的使用者更滿意，並使你的程式庫更受歡迎。
* **分享經驗**。如果你是 Kotlin 愛好者，並樂於透過創作教學內容為 Kotlin 生態系統做出貢獻，在 Kotlin EAP 中試用新功能可讓你有機會成為第一批與社群分享使用這些酷炫新功能經驗的人。
