您可以参与 Kotlin 抢先体验预览（EAP），在最新的 Kotlin 功能正式发布之前抢先体验。

在每次语言版本（_2.x.0_）和工具版本（_2.x.20_）发布之前，我们都会发布抢先体验预览（EAP）构建，供您在实际项目中进行测试并分享早期反馈。
Kotlin EAP 构建通常包含以下阶段：

| EAP 构建 | 描述 |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Beta1** | 引入即将推出的第一批新功能、改进以及其他重大更改。为您提供及早评估新功能性并分享反馈的机会。 |
| **Beta2** | 通常会根据我们收到的反馈添加更多功能和优化。该版本功能完整，并继续预览即将发布的版本，进一步完善先前引入的功能。 |
| **RC**    | 首个候选发布版本（Release Candidate）。侧重于稳定 Beta1 和 Beta2 中交付的更改，并修复测试期间发现的回归错误。 |
| **RC2**   | 包含重要修复，用于完成最终发布的准备并确认就绪状态。 | 

如果您将发现的任何错误报告给我们的问题跟踪器 [YouTrack](https://kotl.in/issue)，我们将不胜感激。
在大多数情况下，我们可以在最终发布之前将其修复，因此您无需等到下一个 Kotlin 版本即可看到您的问题得到解决。

通过参与抢先体验预览并报告错误，您是在为 Kotlin 做出贡献，并帮助我们为[不断壮大的 Kotlin 社区](https://kotlinlang.org/community/)中的每一个人把 Kotlin 做得更好。

如果您有任何问题或想参与讨论，欢迎加入 [Kotlin Slack 中的 #eap 频道](https://app.slack.com/client/T09229ZC6/C0KLZSCHF)。
在此频道中，您还可以收到有关新 EAP 构建的通知。

**[为 Kotlin EAP 版本配置项目](configure-build-for-eap.md)**

> 参与 EAP 即表示您明确知晓：EAP 版本可能不可靠、可能无法按预期工作，并且可能包含错误。
>
> 我们不保证同一版本的 EAP 与最终正式版本之间的兼容性。
>

## EAP 如何帮助您在使用 Kotlin 时更具生产力 {id="how-the-eap-can-help-you-be-more-productive-with-kotlin"}

* **为 Stable 版本做好准备**。如果您负责复杂的超多模块项目，参与 EAP 可以让您在采用 Stable 发布版本时获得更加顺畅的体验。越早更新到 Stable 版本，您就能越早享受到其带来的性能提升和全新语言功能。

  大型且复杂项目的迁移可能需要一些时间，这不仅是因为其规模庞大，还因为某些特定的用例可能尚未被 Kotlin 团队覆盖。通过参与 EAP 并持续测试 Kotlin 新版本，您可以就您的具体用例向我们提供早期反馈。这将帮助我们解决尽可能多的问题，并确保您在正式版本发布时能够安全地更新到 Stable 版本。[了解 Slack 如何通过测试 Android、Kotlin 和 Gradle 的预发布版本获益](https://slack.engineering/shadow-jobs/)。
* **让您的库保持最新**。如果您是库作者，更新到新的 Kotlin 版本至关重要。
  使用较旧的版本可能会阻碍您的用户在其项目中更新 Kotlin。使用 EAP 版本让您能够在 Stable 版本发布的同时，几乎立即在您的库中支持最新的 Kotlin 版本，这能提升用户满意度并提高库的受欢迎程度。
* **分享经验**。如果您是一名 Kotlin 爱好者，乐于通过创建教育内容来为 Kotlin 生态系统做出贡献，那么在 Kotlin EAP 中试用新功能可以让您成为第一批与社区分享这些酷炫新功能使用体验的人。
