你可以参与 Kotlin 抢先体验计划（Early Access Preview，简称 EAP），在最新 Kotlin 功能正式发布前先行试用。

在每个语言版本（_2.x.0_）和工具版本（_2.x.20_）发布前，我们都会提供抢先体验计划（EAP）构建，以便你在真实项目中进行测试并分享早期反馈。
Kotlin EAP 构建通常包含以下阶段：

| EAP 构建 | 描述 |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Beta1** | 引入第一批即将推出的功能、改进及其他重大变更。让你有机会提前评估新功能性并分享反馈。 |
| **Beta2** | 通常会根据我们收到的反馈添加更多功能和优化。该版本功能完整，并继续对即将发布的版本进行预览，使之前引入的功能更加成熟。 |
| **RC**    | 首个发布候选版本（Release Candidate）。侧重于稳定 Beta1 和 Beta2 中交付的变更，并修复测试期间发现的回归错误。 |
| **RC2**   | 包含用于最终确定版本并确认就绪状态的重要修复。 | 

如果你将发现的任何错误报告给我们的问题跟踪器 [YouTrack](https://kotl.in/issue)，我们将不胜感激。
在大多数情况下，我们可以在最终版本发布前将其修复，因此你无需等待下一个 Kotlin 版本即可看到问题得到解决。

通过参与抢先体验计划并报告错误，你将为 Kotlin 做出贡献，并帮助我们为[不断壮大的 Kotlin 社区](https://kotlinlang.org/community/)中的每一个人把 Kotlin 做得更好。

如果你有任何疑问或想加入讨论，欢迎加入 [Kotlin Slack 中的 #eap 频道](https://app.slack.com/client/T09229ZC6/C0KLZSCHF)。在该频道中，你还可以接收有关新 EAP 构建的通知。

**[为 Kotlin EAP 版本配置你的项目](configure-build-for-eap.md)**

> 参与 EAP 即表示你明确承认 EAP 版本可能不稳定、可能无法按预期工作，并且可能包含错误。
>
> 我们不保证同一版本的 EAP 与最终正式版本之间的兼容性。
>

## EAP 如何帮助你提高 Kotlin 生产力 {id="how-the-eap-can-help-you-be-more-productive-with-kotlin"}

* **为稳定版本做好准备**。如果你在负责复杂的多模块项目，参与 EAP 可以使你在采用稳定版本时的体验更加顺畅。越早更新到稳定版本，就能越早利用其性能改进和全新语言功能。

  庞大且复杂的项目迁移可能需要一段时间，这不仅是因为其规模，还因为某些特定用例可能尚未被 Kotlin 团队覆盖。通过参与 EAP 并持续测试 Kotlin 新版本，你可以向我们提供有关你特定用例的早期反馈。这将帮助我们解决尽可能多的问题，并确保你在稳定版本发布时能够安全地进行更新。[了解 Slack 如何通过测试 Android、Kotlin 和 Gradle 预发布版本获益](https://slack.engineering/shadow-jobs/)。
* **使你的库保持最新**。如果你是库作者，更新到新的 Kotlin 版本至关重要。使用旧版本可能会阻碍用户在他们的项目中更新 Kotlin。使用 EAP 版本让你的库几乎可以在稳定版本发布的同时立即支持最新的 Kotlin 版本，这能让你的用户更满意，也能让你的库更受欢迎。
* **分享经验**。如果你是一名 Kotlin 爱好者，乐于通过创建教学内容为 Kotlin 生态系统做出贡献，那么在 Kotlin EAP 中尝试新功能将使你能够率先与社区分享使用这些酷炫新功能的体验。
